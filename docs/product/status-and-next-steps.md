## 2. Что пользователь может сделать сегодня
- Выбрать игру → создать партию на реальной карте → играть **за любую сторону вдвоём за одним устройством** (hot-seat) по срезу правил.
- Играть **против AI** можно только формально: AI пасует, поэтому партия против AI-Повстанцев не может закончиться победой Империи.
- Продолжать партии после перезапуска; старые партии SWR-002…004 открываются на старых mock-правилах.

## 3. Главные пробелы (по отчётам)
1. **AI не играет** — нет AI Commander (самый заметный пробел для продукта «соло против AI»).
2. **Нет боя, миссий, производства, зондов, выбора базы** — правила покрывают только перемещение и раунд.
3. **Технический долг:** Node 20 держит старые версии (NestJS 11, Prisma 6, `openai` 6.x — 7.x требует Node 22); нет CI.
4. **Данные с пометкой «medium»** (вместимость кораблей Повстанцев, способность Мон Мотмы, одна связь карты) — сверить с коробкой.
5. Мелочи: база вычислима из `sessionId` по открытому коду; бейдж «MOCK» не отражает включённый OpenAI; кольцо фокуса на «Тестировать AI».

## 5. Рекомендация
1. **Сначала A — AI Commander v0.** Это главная ценность продукта («играть одному против AI»), и всё нужное уже построено: движок выдаёт допустимые действия, AI-слой умеет безопасно спросить модель и проверить ответ. Начать с детерминированного бота (бесплатно, тестируемо), OpenAI — опционально за флагом и бюджетом. Это сразу закрывает «Империя не может победить против AI» и проверяет весь цикл из blueprint §8.5 до того, как правила усложнятся.
2. **Параллельно — D (маленькая техническая задача):** Node 22 + CI. Она не пересекается с AI по файлам и снимает пины версий.
3. **Затем B — бой**, уже с работающим AI, чтобы каждый новый срез правил сразу проверялся игрой против бота.
4. **E** — когда будет под рукой коробка, 15–30 минут твоего времени.

Решение нужно от PO: какой вариант берём следующим (и стоит ли вести D параллельно).
