## 1. Продуктовая рамка

Это **цифровой компаньон физической партии**, а не Tabletop Simulator: на столе лежат реальные фишки, человек принимает
решения, приложение хранит состояние, показывает допустимые ходы, фиксирует их и (позже) ходит за AI. Отсюда:

- UI — «штабная консоль», а не имитация стола: карта схематична, акцент на информации и действиях.
- Каждое действие — команда серверу; UI ничего не «решает» (цели берутся только из `view.legalActions`).
- Ход на экране должен занимать секунды: человек переносит в приложение то, что уже сделал руками.

## 2. Принципы взаимодействия

| ID | Решение | Почему |
|---|---|---|
| D-P-1 | **Выбор → допустимые действия.** Выбор объекта сразу показывает список доступных команд из `legalActions` и подсвечивает цели на карте. | Пользователь не угадывает правила; UI не содержит правил (AC-12). |
| D-P-2 | **≤ 2 взаимодействия на ход:** (1) выбрать объект, (2) один клик по цели — кнопка в панели **или** подсвеченная система на карте **или** drag на неё. | Требование PO «минимум кликов»; три эквивалентных пути под разные привычки. |
| D-P-3 | **Контекстная панель вместо модалок.** Правая панель меняет содержимое по выбору (ничего / система / объект). Модальных диалогов в основных сценариях нет; подтверждений хода нет. | Модалки прерывают поток и закрывают карту; ход и так атомарен и журналируется. |
| D-P-4 | **Нет hover-only действий.** Hover — только косметика (курсор, лёгкая подсветка). Всё, что даёт hover/drag, доступно кликом и клавиатурой. | Готовность к планшетам и доступность. |
| D-P-5 | **Один источник выбора.** Клик по canvas, по элементу доступного списка и по чипу в панели вызывают одно и то же действие стора (`selectSystem/selectPiece`). | Нет рассинхрона; E2E через список эквивалентен клику по карте. |
| D-P-6 | **Сервер — источник истины, без оптимистичного кеша.** Во время запроса показывается только визуальный «призрак» на цели; кеш меняется только ответом сервера. | Отказ (409/422) не оставляет «залипших» состояний (TC-WEB-08). |
| D-P-7 | **Одна команда в полёте.** Пока команда выполняется, кнопки ходов и drag выключены, выбор остаётся доступным. | Исключает самоконфликты версий (409) от двойных кликов. |
| D-P-8 | **Mock честно помечен** текстом, а не только цветом (см. §9). | Не выдавать временную логику за правила Rebellion (constraint PO). |
| D-P-9 | **Автосохранение без кнопки «Сохранить».** Каждая принятая команда сохранена сервером; в шапке — индикатор «Сохранено». | Сценарий 6; меньше элементов, меньше ошибок. |

## 4. Модель взаимодействия с картой (canvas)

| ID | Жест / ввод | Результат | Почему |
|---|---|---|---|
| D-I-1 | Нажатие на **свой объект, у которого есть цели**, и сдвиг ≥ 4px | Drag объекта (объект становится выбранным) | A-10: drag начинается только с нажатого объекта. |
| D-I-2 | Нажатие **в любом другом месте** (фон, система, линия, чужой/неподвижный объект) и сдвиг ≥ 4px | Pan карты; выбор сохраняется | Большая зона для pan; системы занимают много места, и pan с них естественен. |
| D-I-3 | Нажатие без сдвига (< 4px) на пустом месте | Снять выбор | A-10. |
| D-I-4 | Клик по системе | Выбрать систему — **кроме** случая, когда выбран свой объект и система подсвечена как его цель: тогда клик = команда перемещения | D-P-2 (спецификация: «1 клик по подсвеченной цели на карте»). |

### 4.1 Drag-and-drop объекта

1. Нажатие на свой подвижный объект → после 4px объект «поднимается» (масштаб 1.15, тень), на исходном слоте остаётся полупрозрачный «призрак».
2. Цели (из `legalActions`) уже подсвечены (D-F-1). Под курсором: допустимая цель → утолщённое кольцо + «магнит» (snap-превью слота);
   недопустимая система → красное кольцо + знак ✕; пустое место → без подсветки.
3. Отпускание:
   - на допустимой цели → объект встаёт в слот цели полупрозрачным с кольцом-спиннером, отправляется `MOVE_PIECES`;
     успех → итоговая позиция из нового view; отказ (409/422/сеть) → анимированный возврат (150мс; 0 при reduced motion) + сообщение;
   - на недопустимой системе → **команда не отправляется** (A-16), возврат + сообщение «Нельзя переместить в <Система>: нет допустимого хода»;
   - на пустом месте или на исходной системе → тихий возврат, в aria-live «Перемещение отменено».
4. Drag начатый на объекте никогда не панорамирует карту (TC-E2E-12).

### 13.7 Решения

| ID | Решение | Почему |
|---|---|---|
| D-SW4-1 | Форма — одна страница, 5 нумерованных блоков сверху вниз (сторона → противник → сложность → правила → режим), карточка до 720px. | Всё видно сразу; при дефолтах до старта — 1 клик. |
| D-SW4-2 | Дефолты PO (Повстанцы, AI, Обычная, Base, Digital) при **каждом** монтировании, выбор нигде не запоминается; «последняя сложность» — только в пределах экрана (Q-19). | AC-02; предсказуемость важнее памяти о прошлой партии. |
| D-SW4-3 | Стороны — две крупные карточки-радио с собственной эмблемой, названием, слоганом и полосой цвета фракции; Повстанцы первыми. | Сторона — главное решение; дефолт первым читается как выбранный. |
| D-SW4-4 | Выбранная карточка: рамка primary + фон + ✓ + слово «Выбрано»; невыбранная — без значка. | Состояние не только цветом (WCAG 1.4.1). |
| D-SW4-5 | Эмблемы — абстрактная геометрия (контур vs заливка), без сходства со знаками правообладателя, локальные data-URL. | Права + тот же код «заполнено/контур», что на карте. |
| D-SW4-6 | Противник — сегмент «AI» / «Второй игрок за этим устройством» и живая подпись «AI играет за Империю» / «Второй игрок играет за …». | Пользователь видит последствие выбора стороны сразу (AC-03). |
| D-SW4-7 | Блок сложности убирается из DOM при «Второй игрок»; при возврате к AI — прежнее значение. | AC-04; не показывать неприменимое. |
| D-SW4-8 | Недоступные набор правил и режим видимы, с пометкой «скоро» и подсказкой, `aria-disabled`, не выбираются ни мышью, ни стрелками; текст `text.secondary`, не бледный disabled. | Честно показывает развитие продукта, но не даёт создать неподдерживаемую партию (AC-05). |
| D-SW4-9 | Кнопки: «Начать игру» первой и слева, «Отмена» рядом; на 375 — во всю ширину, «Начать» сверху. | Порядок Tab = визуальный; главное действие первым. |
| D-SW4-10 | Во время запроса: форма `aria-busy`, группы и «Отмена» disabled, кнопка — спиннер и «Создание партии…»; повторный клик/Enter не шлют второй запрос. | AC-10: одна партия на одно намерение. |
| D-SW4-11 | Ошибка — inline `role="alert"` над кнопками, человеческий текст + что делать; значения сохраняются; фокус на «Начать игру», alert прокручивается в зону видимости. | AC-07; не терять выбор, повтор в одно нажатие. |
| D-SW4-12 | Любое изменение поля скрывает прошлую ошибку; повтор отправки — новая попытка (новый ключ, Q-5). | Ошибка относится к прошлым настройкам. |
| D-SW4-13 | Примечание «Прототип: тестовая расстановка, не правила оригинальной игры» над кнопками вместо бейджа MOCK в заголовке. | AC-13; пояснение полезнее непонятного «MOCK». |
| D-SW4-14 | На 375 карточки и сегменты складываются в столбец, без sticky-панели. | Нет горизонтального скролла; sticky перекрыл бы alert и фокус (WCAG 2.4.11). |
| D-SW4-15 | Строка партии: сторона · противник (+сложность только для AI) · раунд/фаза; вторая строка — чип статуса и время (`<time>` с абсолютной датой в title). Ruleset/mode не показываются, пока выбор единственный. | AC-09; статус и дата сканируются отдельно от сути. |
| D-SW4-16 | Статус сессии — чип «иконка + слово»: Настройка / Прототип / Идёт / Завершена; «Прототип» в списке, в «Продолжить» и на столе (Q-21). | AC-13; не только цветом. |
| D-SW4-17 | На столе бейдж MOCK заменён чипом с полным текстом «Прототип: тестовая расстановка, не правила оригинальной игры» (`prototype-badge`), переносится, а не обрезается. | AC-13, TC-C-16; пользователь понимает, что именно ненастоящее. |
| D-SW4-18 | Шапка стола — 4 группы (навигация, стороны, состояние, статус): ≥1200 один ряд; 600–1199 два ряда; <600 до четырёх рядов; перенос всегда вместо горизонтальной прокрутки. | D-1: 1024 и 768 обязательны (Q-22); ничто не прячется за скроллом. |
| D-SW4-19 | В human-партии в шапке «Ход: <сторона>» и кнопка «Передать ход» (без подтверждения); в AI-партии кнопки нет. | Кто ходит — всегда на виду; заслонка сама служит паузой. |
| D-SW4-20 | Заслонка передачи хода заменяет весь стол: эмблема и название следующей стороны, раунд/фаза, «Прототип», одна кнопка «Я — <сторона>»; ни карты, ни сайдбара, ни журнала. | AC-14; нечего подсмотреть, даже через DevTools/`__boardDebug`. |
| D-SW4-21 | При появлении заслонки фокус на заголовке, не на кнопке; первый Tab — «Я — <сторона>». | Игрок A не «примет» ход повторным Enter за игрока B. |
| D-SW4-22 | Под кнопкой — честная оговорка: подтверждение не проверяет личность. | Без аутентификации это доверительный обмен (spec). |
| D-SW4-23 | Заслонка и смена стороны — без анимаций; переходы карточек и Collapse — 0 мс при reduced motion; спиннер остаётся. | D-A-9; движение не несёт смысла. |
| D-SW4-24 | Контраст: эмблемы/полосы ≥ 3:1, тексты (в т.ч. «скоро», «Выбрано», бейдж, заслонка) ≥ 4.5:1 к своему фону; фокус — общий `:focus-visible` (D-A-5). | WCAG 1.4.3 / 1.4.11 / 2.4.7. |
