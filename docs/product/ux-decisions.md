## 1. Продуктовая рамка

Это **цифровой компаньон физической партии**, а не Tabletop Simulator: на столе лежат реальные фишки, человек принимает
решения, приложение хранит состояние, показывает допустимые ходы, фиксирует их и (позже) ходит за AI. Отсюда:

- UI — «штабная консоль», а не имитация стола: карта схематична, акцент на информации и действиях.
- Каждое действие — команда серверу; UI ничего не «решает» (цели берутся только из `view.legalActions`).
- Ход на экране должен занимать секунды: человек переносит в приложение то, что уже сделал руками.

## 2. Принципы взаимодействия

| ID | Решение | Почему |
|---|---|---|
| D-P-1 | **Выбор → допустимые действия.** Выбор объекта сразу показывает список доступных команд из `legalActions` и подсвечивает цели на карте. | Пользователь не угадывает правила; UI не содержит правил (AC-12). |
| D-P-2 | **≤ 2 взаимодействия на ход:** (1) выбрать объект, (2) один клик по цели — кнопка в панели **или** подсвеченная система на карте **или** drag на неё. | Требование PO «минимум кликов»; три эквивалентных пути под разные привычки. |
| D-P-3 | **Контекстная панель вместо модалок.** Правая панель меняет содержимое по выбору (ничего / система / объект). Модальных диалогов в основных сценариях нет; подтверждений хода нет. | Модалки прерывают поток и закрывают карту; ход и так атомарен и журналируется. |
| D-P-4 | **Нет hover-only действий.** Hover — только косметика (курсор, лёгкая подсветка). Всё, что даёт hover/drag, доступно кликом и клавиатурой. | Готовность к планшетам и доступность. |
| D-P-5 | **Один источник выбора.** Клик по canvas, по элементу доступного списка и по чипу в панели вызывают одно и то же действие стора (`selectSystem/selectPiece`). | Нет рассинхрона; E2E через список эквивалентен клику по карте. |
| D-P-6 | **Сервер — источник истины, без оптимистичного кеша.** Во время запроса показывается только визуальный «призрак» на цели; кеш меняется только ответом сервера. | Отказ (409/422) не оставляет «залипших» состояний (TC-WEB-08). |
| D-P-7 | **Одна команда в полёте.** Пока команда выполняется, кнопки ходов и drag выключены, выбор остаётся доступным. | Исключает самоконфликты версий (409) от двойных кликов. |
| D-P-8 | **Mock честно помечен** текстом, а не только цветом (см. §9). | Не выдавать временную логику за правила Rebellion (constraint PO). |
| D-P-9 | **Автосохранение без кнопки «Сохранить».** Каждая принятая команда сохранена сервером; в шапке — индикатор «Сохранено». | Сценарий 6; меньше элементов, меньше ошибок. |

## 4. Модель взаимодействия с картой (canvas)

| ID | Жест / ввод | Результат | Почему |
|---|---|---|---|
| D-I-1 | Нажатие на **свой объект, у которого есть цели**, и сдвиг ≥ 4px | Drag объекта (объект становится выбранным) | A-10: drag начинается только с нажатого объекта. |
| D-I-2 | Нажатие **в любом другом месте** (фон, система, линия, чужой/неподвижный объект) и сдвиг ≥ 4px | Pan карты; выбор сохраняется | Большая зона для pan; системы занимают много места, и pan с них естественен. |
| D-I-3 | Нажатие без сдвига (< 4px) на пустом месте | Снять выбор | A-10. |
| D-I-4 | Клик по системе | Выбрать систему — **кроме** случая, когда выбран свой объект и система подсвечена как его цель: тогда клик = команда перемещения | D-P-2 (спецификация: «1 клик по подсвеченной цели на карте»). |
| D-I-5 | Клик по объекту | Выбрать объект (повторный клик — без изменений, не toggle) | Toggle легко сбросить случайно. |
| D-I-6 | Колесо мыши / тачпад-pinch (ctrl+wheel) | Zoom вокруг курсора, шаг ×1.1 за «щелчок», прокрутка страницы подавляется | Конвенция картографических приложений; точка под курсором остаётся на месте (TC-E2E-08). |
| D-I-7 | Кнопки `+` / `−` / «вписать» (DOM поверх canvas, справа снизу) + индикатор «100%» | Zoom вокруг центра ×1.25; «вписать» — все системы с отступом 64px; `+`/`−` disabled на пределах | A-9; кнопки доступны клавиатуре и тачу. |
| D-I-8 | Пределы масштаба | `MIN_SCALE = 0.4`, `MAX_SCALE = 2.5` (константы FE) | A-9; при < 0.4 подписи нечитаемы, > 2.5 — бесполезно. |
| D-I-9 | `Esc` | Во время drag — отмена drag и откат; иначе — снять выбор (если фокус не в поле ввода/меню) | Единый «аварийный выход». |
| D-I-10 | Клавиатура при фокусе на карте | `←↑→↓` — pan на 80px, `+`/`=` и `−` — zoom, `0` — вписать, `Esc` — снять выбор | Управление видом без мыши; выбор/ход с клавиатуры — через список (§6). |
| D-I-11 | Курсоры | `grab`/`grabbing` — фон; `pointer` — система/объект; `move` — перетаскиваемый объект; при наведении на подсвеченную цель при выбранном объекте — `copy`-подобный `pointer` + подсказка «Переместить сюда» в списке/панели | Предсказуемость жестов; hover — только косметика. |
| D-I-12 | Начальный вид | «Вписать» при первом открытии партии; вид сохраняется в памяти при возврате к той же партии в рамках сессии | Карта сразу целиком; без сюрпризов при навигации. |

### 4.1 Drag-and-drop объекта

1. Нажатие на свой подвижный объект → после 4px объект «поднимается» (масштаб 1.15, тень), на исходном слоте остаётся полупрозрачный «призрак».
2. Цели (из `legalActions`) уже подсвечены (D-F-1). Под курсором: допустимая цель → утолщённое кольцо + «магнит» (snap-превью слота);
   недопустимая система → красное кольцо + знак ✕; пустое место → без подсветки.
3. Отпускание:
   - на допустимой цели → объект встаёт в слот цели полупрозрачным с кольцом-спиннером, отправляется `MOVE_PIECES`;
     успех → итоговая позиция из нового view; отказ (409/422/сеть) → анимированный возврат (150мс; 0 при reduced motion) + сообщение;
   - на недопустимой системе → **команда не отправляется** (A-16), возврат + сообщение «Нельзя переместить в <Система>: нет допустимого хода»;
   - на пустом месте или на исходной системе → тихий возврат, в aria-live «Перемещение отменено».
4. Drag начатый на объекте никогда не панорамирует карту (TC-E2E-12).
