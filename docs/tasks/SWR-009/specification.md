## 1. Business goal

Игровой стол и платформа получают утверждённый визуальный язык «Galactic Vector Terminal», при этом **все** существующие игровые
сценарии продолжают работать, а новые элементы (маркеры групп, Unit Manifest, подсветка недавних действий AI) строятся только
на данных серверного `PlayerView`.

## 2. Сценарии

- **S-1. Партия против AI (главный).** Новая партия «Повстанцы vs AI (бот)» → стол-консоль → взять лидера → цели подсвечены
  → активировать систему → переместить юниты → «Завершить активацию» → AI ходит (LED «выполняет ход», затем «готов · N действий»,
  системы недавних действий AI отмечены красным пунктиром, строки журнала с меткой AI) → пас с подтверждением → новый раунд → … → итог.
- **S-2. Осмотр войск.** Клик/Enter по маркеру группы на карте (или по системе) → инспектор rail показывает Unit Manifest: система,
  регион, фракции, группы по арене, строки «тип × N», лидеры, итог; «Закрыть» возвращает к выбранной системе. На мобильном —
  нижний лист.
- **S-3. Империя и скрытая база.** Империя (vs AI-Повстанцы или hot-seat): скрытая зона базы и её манифест показывают только то,
  что прислал сервер, с пометкой ограниченной видимости; ни карта, ни манифест, ни подписи, ни a11y-тексты не называют систему базы.
- **S-4. Hot-seat.** Заслонка передачи устройства в новом стиле; стол скрыт полностью.
- **S-5. Навигация.** Каталог → страница игры → новая партия → стол → «← К игре» / ⚙ настройки → назад; 404 и «партия не найдена».
- **S-6. Мобильный 375×812 и планшет.** Стол — одна колонка, карта ≈ 65vh, rail ниже, манифест — нижний лист, без горизонтальной прокрутки.

## 3. Правила и ограничения дизайна

- R-1. Токены — единый модуль (палитра UI Kit, PT Mono, размеры шрифта, границы/безели, радиус 1 px, отступы); MUI-тема и Konva-стили
  берут значения **только** из токенов. Цвета игры (Империя = Signal Red `#DD6B59`, Повстанцы = Bright Phosphor `#91DFA1`)
  обновляются в `rebellionVisualTokens` или переопределяются в web-теме игры (решение лида; одно место истины).
- R-2. Семантика цвета (UI Kit): фосфор — доступное действие/информация; янтарь — выбор, фокус, подтверждение; красный — Империя,
  AI-события, критическое. Признак никогда не передаётся только цветом (форма глифа, пунктир, текст).
- R-3. Глифы: флот Империи — залитый треугольник; флот Повстанцев — контурный треугольник; наземные Империи — залитый квадрат;
  наземные Повстанцев — контурный квадрат; лидер — ромб (янтарный контур); допустимая цель — пунктирное фосфорное кольцо;
  выбор — янтарное кольцо (+ перекрестие); недавнее действие AI — красное пунктирное кольцо. Счётчик у глифа = число фигур этой
  группы (сторона × арена) в системе по `view.units`; флот и наземные — разные маркеры.
- R-4. Карта: регионы — только штриховая граница `#66846A` без заливки + подпись; маршруты `#456B4D`; узлы — тёмная заливка,
  фосфорный контур; подписи `#B9C2B4`; фон — CRT `#030704`…`#080F09` с сеткой; scanlines — декоративный DOM-слой с `pointer-events: none`.
  Растровая подложка запрещена.
- R-5. Unit Manifest строится только из `view` (без вычисления скрытого): системные юниты — по `location.systemId`; юниты в скрытой
  зоне — только в манифесте скрытой зоны. Без «силы армии», без демо-текстов.
- R-6. Тексты — через i18n (ru/en); числа — из `view`/автоматизации; декоративные надписи макета, изображающие данные
  («SECTOR SCAN 04», «DESIGN ITERATION 03», «16:47»), не переносятся или заменяются реальными значениями (версия правил, зум, время записи).
- R-7. Все существующие `data-testid`, роли, aria-атрибуты и клавиатурные пути сохраняются (или e2e обновляются осознанно, с записью
  в плане); debug-API карты для e2e сохраняет контракт.

## Acceptance criteria (testable)

Раздел 4 спецификации.

- **AC-1:** В задаче есть `design-analysis.md`: инвентарь токенов, компонентов и состояний всех четырёх прототипов (HTML/CSS/JS/изображение) с маппингом на React/MUI/Konva и списком демо-элементов, которые не переносятся.
- **AC-2:** Стек не изменён: в `package.json` не добавлено UI/state/canvas-библиотек; допускается только пакет шрифта PT Mono (OFL) — см. A-1. Нет растровой подложки карты в `apps/web`.
- **AC-3:** Дизайн-токены UI Kit — в одном модуле; MUI-тема построена из них (палитра, PT Mono, типографическая шкала 28/19/14/22/11, радиус, overrides Button/IconButton/TextField/Select/Switch/Tabs/Dialog/Alert/Chip/Tooltip). Переиспользуемые компоненты UI Kit (минимум: `TerminalModule`/панель с шапкой, `Led`, `KeyButton`-варианты через тему, `StatusBadge`, `UnitGlyph`/`CounterMarker`, `LegendKey`) лежат в общем UI-слое и покрыты unit-тестами. Контраст текстовых токенов к фонам ≥ 4.5:1 (unit-тест).
- **AC-4:** Карта рисуется в Konva из `view.map` + `coreMapLayout`/`coreRegionShapes`: 32 системы, 69 связей, 8 регионов (unit-тест модели сцены и e2e через debug-API); стили R-4; нет растра.
- **AC-5:** Состояния систем на карте: допустимая цель, выбранная, активированная, источник перемещения, спорная, удалённая, база (только если сервер её показывает), недавнее действие AI — визуально различимы по R-2/R-3 и проверены unit-тестами модели/рендера.
- **AC-6:** Маркеры групп: для каждой системы и стороны отдельные маркеры флота и наземных сил со счётчиком = число юнитов группы из `view.units`; лидеры на карте — ромб. Маркер — фокусируемая/кликабельная цель, открывающая Unit Manifest (мышь, клавиатура; на компактном LOD — по системе).
- **AC-7:** Unit Manifest (rail на desktop, нижний лист < 760 px): система, регион, фракции, группы по стороне × арене со строками «тип × N», лидеры, итог; состояния: только флот, флот+наземные, обе фракции, только лидер, пустая система, ограниченная видимость (скрытая зона). Выбор маркера выделяет его группу. «Закрыть» возвращает к выбранной системе. Покрыто unit-тестами модели и компонента.
- **AC-8:** Скрытая информация: у Империи до раскрытия ни карта, ни манифест, ни подписи/aria/DOM не называют систему базы; манифест скрытой зоны показывает только присланное сервером. `pnpm check:bundle` зелёный; e2e `core-hidden-base` зелёный; новый unit-тест манифеста на редактированном виде Империи.

## 5. Assumptions

- A-1. PT Mono подключается локально через пакет `@fontsource/pt-mono` (OFL-1.1, только шрифт), а не через Google Fonts:
  без внешних запросов в рантайме. Fallback — `ui-monospace, monospace`. Это не смена стека.
- A-2. Отдельных макетов для каталога/страницы игры/настройки партии/настроек нет: этап Navigation переводит их на новую тему и
  terminal-шапку без смены структуры экранов.
- A-3. «Реальная геометрия» = `coreMapLayout`/`coreRegionShapes` текущего движка (собственная схема по относительному
  расположению реальной карты). Макет карты — скриншот этой же схемы, поэтому совпадение проверяется визуально.
- A-4. Ширина rail: ≥ 1400 px — ≈ 530 px как в макете; 1200–1399 — 440; 900–1199 — 320–360 (макет при ≤ 1100 — 300). Высоты модулей rail
  гибкие (контент реальный, длиннее демо). Точные значения — в плане лида.
- A-5. Цвета сторон меняются на палитру UI Kit (Империя — красный, Повстанцы — фосфор) во всём приложении, включая
  карточки фракций на экране настройки; эмблемы сторон сохраняются (собственная графика).
- A-6. Подсветка «недавнее действие AI» держится до следующей команды игрока или следующего прогона AI (совпадает со сводкой хода AI).
- A-7. Dev-only страница-витрина UI Kit (`/dev/ui-kit`) допустима для визуальной сверки, если она не попадает в production-бандл
  (как `/dev/ai`, проверяется `check:bundle`). Решение — за лидом; без неё сверка UI Kit делается по реальным экранам.
- A-8. LOD карты сохраняется: в компактном режиме маркеры групп упрощаются (один маркер на сторону с общим числом фигур), но
  по-прежнему ведут к манифесту системы.

## 6. Risks

- RK-1. Большой визуальный рефакторинг ломает e2e, завязанные на testid/координаты canvas → R-7, полный прогон e2e на INTEGRATION.
- RK-2. Утечка базы через новые элементы (манифест, AI-отметки, aria) → AC-8, отдельный review-фокус.
- RK-3. Плотная консоль на 1024–1280 px → AC-13, скриншоты 1024×768 и 1280×800.
- RK-4. Регрессия контраста при новой палитре → unit-тест контраста + e2e a11y.
- RK-5. Объём: много файлов в одной зоне → разбиение по OWNED FILES без пересечений, интеграция лидом.

## 7. Out of scope

- Изменения правил/game-core/серверной фильтрации и API (кроме, при необходимости, визуальных токенов в `@bga/game-rebellion/assets`).
- Новые игровые механики, анимации ходов AI (кроме статичной подсветки), звук, светлая тема, 3D.
- Редизайн `/dev/ai` сверх наследования темы; legacy-стол `mock-v1` — только наследует тему, отдельной вёрстки нет.

## 8. Clarifications (решения Analyst, 2026-11-21, по вопросам QA Q-1…Q-8)

- QD-2 (Q-2). Узлы Konva не фокусируются по Tab. Клавиатурный путь к манифесту — через DOM: выбор системы (список «Объекты»,
  клавиатура карты) → инспектор rail показывает манифест системы; маркеры на карте — цели мыши/касания. Это удовлетворяет AC-6.
- QD-3 (Q-3). Отметки «недавнее действие AI» строятся из `automation.lastRun`; если после перезагрузки платформа его не

- QD-4 (Q-4). Группировка — по арене `unitTypes[].arena`: всё, что не `space`, — наземная группа (сооружения входят в неё на карте и

- QD-5 (Q-5). При взятом лидере клик по маркеру = клик по его системе (действует существующая логика активации/выбора);
  манифест открывается только вне режима «лидер взят».
- QD-6 (Q-6). Спек визуальной сверки (`file://`-макеты) в `pnpm verify`/CI не входит; запускается QA вручную, скриншоты — в артефактах.
- QD-7 (Q-7). Недостижимые со старта состояния манифеста достигаются только реальной игрой через API/UI (существующие e2e-хелперы,
  которые шлют настоящие команды). Подделывать состояние в БД нельзя. Недостижимое в `core-v1` — `not_run` с причиной.
- QD-8 (Q-8). Пограничный контраст решаем заранее: `#DD6B59` и `#5E8D68` — только для глифов, рамок, LED (не-текст, ≥ 3:1);
