## Дополнение PO (2026-11-08): валидатор переменных окружения
Запрос PO в чате: «докинем валидатор на енвы, чтоб все обязательные поля енвов были заполнены всегда». Требования (уточняются в спецификации):
- Одна Zod-схема окружения backend (например `apps/api/src/config/env.ts`) — единственное место чтения `process.env` в `apps/api/src`
  (сейчас: `DATABASE_URL` в `app.factory.ts`, `PORT` в `main.ts`); проверка один раз при старте, fail-fast.
- Обязательны всегда: `DATABASE_URL`; `PORT` — целое (значение по умолчанию допустимо, если явно описано в схеме);
  `OPENAI_ENABLED` — boolean. При `OPENAI_ENABLED=true` обязательны и валидны: `OPENAI_API_KEY` (непустой),
  `OPENAI_STRATEGY_MODEL`, `OPENAI_TACTICAL_MODEL`, `OPENAI_MAX_COST_PER_SESSION_USD` (> 0).
- Ошибка перечисляет имена отсутствующих/невалидных переменных и причину; **значения (особенно ключ) не выводятся** ни в
  сообщение, ни в логи.
- `apps/api/.env.example` содержит все переменные схемы (ключ — пустой); тест сверяет ключи `.env.example` со схемой, чтобы
  новая обязательная переменная не могла появиться без примера.
- e2e/тесты задают нужные переменные явно (mock-провайдер не требует ключа).
