## Решения PO на INTAKE (AskUserQuestion, 2026-11-19)
- **PO-1 (победа Империи против AI):** «Зависит от сложности». easy — AI-Повстанцы часто уводят юниты из базы (рейды/«расширение»);
  normal — иногда оставляют базу пустой под угрозой; hard — всегда держат охрану. Победа Империи против AI достижима на
  easy/normal; на hard — только после среза «бой».
- **PO-2 (включение OpenAI):** «Только env-флаг» — `AI_COMMANDER_PROVIDER=bot|openai` (плюс `OPENAI_ENABLED=true`); в UI только
  показ, кто ходит; без новых полей настройки партии.

> SWR-006 — AI Commander v0: первый полноценный ход ИИ
> Контекст
> Продолжаем разработку проекта `dimatitov/bga`. Текущее состояние: ветка `main`, последний известный коммит `7195758` (фактически main сейчас на `c1ace26` — только документ статуса). Все предыдущие задачи SWR-000, SWR-002, SWR-003, SWR-004, SWR-005 и SWR-005B приняты. Цель продукта — универсальная платформа для игры в физические настольные игры против ИИ. Первая игра — Star Wars: Rebellion, следующая — Forbidden Stars. Главная задача текущей итерации: сделать ИИ реальным участником партии, способным самостоятельно выбирать и выполнять допустимые действия.
> 1. Перед началом разработки
> Изучи актуальный репозиторий: архитектурный blueprint; инструкции агентной команды и workflow; `docs/tasks/` и отчёты предыдущих задач; существующий Command API; Game Core и механизм `legalActions`; AI-слой из SWR-005B; текущую реализацию AI-pass; механизмы сохранения партий и защиты скрытой информации. Не предполагай, что архитектура устроена определённым образом, пока не проверишь код. Используй существующую агентную систему разработки. Назначь необходимые роли, организуй реализацию, проверки и приёмку в соответствии с принятым workflow. Создай задачу SWR-006 и необходимые документы в установленной проектом структуре.
> 2. Целевой пользовательский сценарий
> Пользователь создаёт новую партию Star Wars: Rebellion. Настройки: человек играет за Повстанцев; противник — AI; сложность — Normal; AI-провайдер — Deterministic или OpenAI, в зависимости от конфигурации. После начала партии: 1) человек выполняет действия за свою сторону; 2) когда управление переходит к ИИ, система самостоятельно запускает AI Commander; 3) AI получает доступное ему состояние игры и список допустимых действий; 4) AI выбирает действие; 5) сервер проверяет действие через существующий игровой движок; 6) действие применяется, состояние партии обновляется; 7) пользователь видит результат и запись в истории партии; 8) если ИИ должен продолжать ходить, цикл повторяется с учётом правил и ограничений; 9) партия сохраняется и может быть продолжена после перезапуска. Необходимо проверить весь цикл до завершения партии в рамках реализованного среза правил. Важно: AI должен уметь играть за обе фракции. Проверить сценарии AI Empire и AI Rebels.
> 3. Архитектура AI Commander — две стратегии.
> 3.1 Deterministic Commander — бесплатный бот без OpenAI: выбирает только из допустимых действий; работает без API-ключа и интернета; при одинаковом состоянии и конфигурации принимает воспроизводимые решения; учитывает хотя бы элементарные игровые цели своей стороны; не ограничивается постоянным `pass`; умеет завершать фазу, когда других допустимых действий нет или они нецелесообразны; не создаёт бесконечные циклы; может использоваться для автоматического прогона партий и тестирования новых механик. Не нужно строить сложный шахматный движок или полноценный поиск дерева решений; начать с простых правил оценки допустимых действий.
> 3.2 OpenAI Commander — использовать инфраструктуру SWR-005B. AI должен: получать игровое состояние с точки зрения своей фракции; видеть только разрешённую ему информацию; получать список допустимых действий; анализировать ситуацию и выбирать действие; возвращать структурированный результат по существующему контракту либо его обоснованному расширению. Предпочтительная схема: Game State → Player View → Legal Actions → AI Decision → Validation → Command API → Updated State. Вся логика изменения состояния остаётся на сервере. OpenAI не должен: напрямую менять состояние игры; создавать произвольные команды вне `legalActions`; получать скрытую базу Повстанцев, если она неизвестна Империи; видеть приватную информацию противника; обходить проверки движка. Не отправлять модели внутренний полный state, если он содержит закрытые данные. Предусмотреть защищённый идентификатор допустимого действия или эквивалентный механизм выбора, исключающий произвольные параметры от модели.
> 4. Стратегическое поведение
> На первом этапе не нужна идеальная стратегия. Нужно осмысленное поведение в пределах SWR-005: активация систем лидерами; перемещение юнитов; выбор между доступными действиями; учёт целей Империи и Повстанцев; разумный переход к следующей фазе; корректное завершение раунда; реакция на изменение игрового состояния. Если действие не имеет стратегической ценности, бот может предпочесть другое действие или pass. Для OpenAI — короткий системный промпт: роль фракции, цель, правила видимости и формат выбора. Не заставлять модель самостоятельно вычислять правила, которые уже проверяет Game Core.
> 5. Автоматическое выполнение
> Надёжный механизм запуска AI после действий человека: AI запускается только когда действительно должен действовать; нет параллельных конфликтующих запросов; двойное нажатие или обновление страницы не приводит к двойному ходу; после перезапуска сервера партия остаётся корректной; AI не выполняет действия за человека; один ошибочный ответ модели не ломает партию; есть ограничение количества последовательных AI-действий; есть защита от бесконечного цикла; у пользователя есть понятный индикатор «ИИ думает». Использовать существующую модель сессий, сохранений и Command API. Не создавать отдельный независимый игровой движок для AI.
> 6. OpenAI: стоимость, ошибки, резервный режим
> Использовать механизмы бюджета и телеметрии SWR-005B: конфигурация провайдера; лимит расходов на партию; учёт токенов и стоимости; таймаут запросов; обработка сетевых ошибок; обработка невалидного ответа; повторные запросы только в разумных пределах; переход на Deterministic Commander при недоступности OpenAI; отображение причины fallback в диагностике. При исчерпании лимита расходов AI должен продолжать игру бесплатно, а не блокировать партию. API-ключ остаётся исключительно на сервере. Не отправлять пользовательские данные, не необходимые для решения игрового действия.
> 7. Интерфейс
> Интегрировать AI Commander в текущий UX партии. Пользователь должен видеть: какой противник выбран; какой провайдер AI активен, если эта настройка доступна пользователю; когда AI обдумывает действие; какое действие выполнил AI; когда использован fallback. История партии должна фиксировать действия AI. Не нужно создавать отдельный большой интерфейс управления ИИ. Сохранить существующий стиль приложения.
> 8. Тестирование — обязательные тесты: 1) Deterministic AI выбирает допустимые действия; 2) OpenAI AI выбирает допустимые действия; 3) невалидный ответ модели отклоняется; 4) AI не получает скрытую информацию соперника; 5) AI не выполняет команду за чужую сторону; 6) повторный запрос не приводит к двойному действию; 7) ошибка OpenAI активирует fallback; 8) превышение бюджета активирует fallback; 9) AI способен играть за Империю; 10) AI способен играть за Повстанцев; 11) партия корректно сохраняется и восстанавливается; 12) есть автоматический тест последовательности нескольких ходов; 13) нет бесконечных циклов и неконтролируемых расходов; 14) работа без OpenAI API-ключа не нарушается. Использовать mock-провайдер для CI и большинства тестов. Реальные вызовы OpenAI не должны выполняться при обычном `pnpm verify`.
> 9. Критерии приёмки — SWR-006 принимается, когда: создана и документирована задача SWR-006; AI автоматически вступает в игру; Deterministic Commander работает без внешних сервисов; OpenAI Commander использует интеграцию SWR-005B; оба провайдера применяют действия через существующий Command API; сохраняется изоляция скрытой информации; работают ограничения расходов и fallback; партии сохраняются и восстанавливаются; AI работает за обе фракции; UI показывает выполнение действий AI; добавлены модульные, интеграционные и e2e-тесты; `pnpm verify` проходит полностью; агентная система выполнила предусмотренные проверки и приёмку; сформирован `delivery-report.md`.
> 10. Ограничения — не реализовывать в SWR-006: космические и наземные бои; полную систему миссий; производство юнитов; зонды; полный набор карт; Forbidden Stars; обновление Node и инфраструктуры CI (это делает параллельная SWR-007). Не переписывать существующие подсистемы без необходимости. Соблюдать текущую архитектуру и принятые проектные решения.
> 11. Результат — пользователь может запустить Star Wars: Rebellion против AI, выполнить собственные действия, увидеть осмысленные ответные действия бота и продолжать партию без второго человека.
